AI MIRROR PROJECT · LOCAL CLI · BETA

Never trust AI with your codebase.
Let it touch only the mirror.

AIMP gives every AI harness its own local Git workspace. You review the exact paths, reports, and deletions before an approved batch crosses back into the original project.

Get started →View on npm ↗
$ npm install -g @bbliong/aimp@beta

THE BOUNDARY

AI works in a copy. You stay in control.

ORIGINAL PROJECTprotected
~/projects/shop-api
  • Real credentials stay here
  • You run tests and the app here
  • You commit with your normal workflow
review⇄sync
AI MIRRORisolated
~/ai-mirrors/shop-api-ai
  • AI edits this independent Git repo
  • Placeholders replace excluded files
  • Every sync creates a local checkpoint

● AIMP never calls a model, runs your application, creates a commit in the original, or pushes to a remote.

01 · QUICK START
From zero to a reviewed change
Use any harness or AI tool. AIMP only manages the boundary and the Git trace.




01
Initialize from the original
Run AIMP in the project you trust. Choose a separate mirror folder for the current branch.
cd ~/projects/shop-api
aimp
$ /init
Mirror folder: ~/ai-mirrors/shop-api-ai


02
Open the mirror with your AI
The mirror receives AGENTS-AIMP.md and AIMP_REPORT.md. The rules tell the harness to stay inside this folder and complete the report after each batch.
cd ~/ai-mirrors/shop-api-ai
codex                 # or any other harness


03
Review and sync deliberately
Return to the original, inspect the paths and diff, then approve the batch. The original remains uncommitted.
cd ~/projects/shop-api
aimp
$ /status
$ /diff
$ /sync









02 · COMMAND REFERENCE
A small, explicit command surface
Commands are available according to where AIMP is running: the original project or its mirror.


CommandWherePurpose


/initOriginalCreate or select the mirror for the current branch.


/reinitOriginalReplace or relocate a mirror after confirmation; keep a backup.


/useOriginalExplicitly switch the mirror to the current original branch.


/statusBothShow paths, paired branches, dirty state, pending AI work, and changed paths.


/diffBothPreview changed paths and text diffs without writing files.


/syncOriginalApply the reviewed AI batch to the original and checkpoint the mirror.


/sync-original-to-aiOriginalRefresh the mirror from committed original changes.


/serializeMirrorAdopt selected mirror changes as its local baseline without touching the original.


/get-summaryBothRead the ready summary from AIMP_REPORT.md.


/get-commit-messageBothRead the proposed commit subject from the report.


/recoverOriginalResume an interrupted transaction.


/recover rollbackOriginalRestore the transaction backup instead of resuming.


/doctorOriginalCheck Git, state, pairing, repository shape, and recovery readiness.


/migrateOriginalBack up and migrate legacy AIMP state.


/adopt-baselineOriginalAcknowledge a reviewed legacy baseline.


/adopt-policyOriginalReview and accept a changed .aimpignore policy.


/listOriginalList branch pairs and mirror locations.


/logOriginalShow local transaction receipts.


/language en|idBothChange the interface language. New projects default to English.


/helpBothShow commands available in the current mode.


/exitBothExit and restore the previous terminal screen.




Non-interactive examples: aimp --plain status --json, aimp --plain sync --dry-run, aimp --version.

04 · POLICY
Keep secrets out with .aimpignore
The policy lives in the original project and applies in both directions, even to files already tracked by Git. AIMP copies, deletes, and applies only included paths.
# original/.aimpignore
.env
*.local
private/
!private/example.env


REPORT CONTRACT
Make every batch reviewable
AIMP_REPORT.md is the AI's handoff. It must contain the generated identity, a summary, a one-line commit message, test results, notes, and Status: ready.
  • Identity matches the active branch and batch
  • Changed paths are visible in /diff
  • Deletions and overwritten original paths require confirmation
  • No original-project commit is created by AIMP







05 · BRANCHES & RECOVERY
Explicit branch pairing. Recoverable operations.


One mirror, paired branches
Each original branch maps to a branch with the same name in the mirror. Switch the original, then run /use. AIMP blocks a switch while the active mirror has pending work.
Reverse refresh is manual
After committing in the original, run /sync-original-to-ai. The original must be clean and the mirror must have no pending changes.
Interrupted? Stop and recover
Run /doctor, then /recover to resume or /recover rollback to restore the backup. Never delete AIMP state to silence a recovery warning.







06 · INSTALLATION
Install the beta


npm install -g @bbliong/aimp@beta
aimp --version
Requirements: Node.js 22.14+, Git 2.34+, Linux or WSL2 on a Linux filesystem.
AIMP is a local boundary tool. It does not sandbox an AI process running as the same OS user; your OS permissions still matter.
